# 编码规范

## 通用原则

- 先表达业务含义，再考虑抽象复用。
- 优先小改动，不做与需求无关的重构。
- 跨层数据使用明确类型，不传递无约束 JSON 或字符串状态。
- 注释说明安全原因、系统约束或非显然取舍，不复述代码。
- 新增生产依赖前说明用途、替代方案和供应链影响。

## TypeScript 与 React

- 开启严格类型检查，不使用无理由的 `any`。
- 页面放在 `src/pages/`，可复用 UI 放在 `src/components/`。
- 所有 Tauri IPC 封装在 `src/api/`，组件不得直接调用 `invoke`。
- 业务状态类型放在 `src/types/`，纯校验与格式化放在 `src/lib/`。
- 浏览器开发 fallback 不得模拟截图、LLM 请求或删除成功。

## Rust

- 平台 API 类型只能存在于 `capture/windows.rs` 或
  `capture/macos.rs` 等适配层。
- 安全敏感输入先做长度、范围、枚举和路径校验。
- 可恢复错误返回 `Result`；仅在无法继续启动时使用 `expect`。
- 日志使用结构化字段和脱敏错误码，不记录敏感值。
- 密钥类型应在释放时清零，明文缓冲区生命周期保持最短。
- 数据库变化必须使用迁移，不得在运行时拼接 schema。

## 错误处理

- UI 显示用户可执行的修复方式。
- 日志记录任务 ID、阶段、耗时和脱敏错误码。
- LLM 请求失败不得伪装成本地截图失败；本地高风险错误必须停止截图。
- 密文损坏、摘要不匹配和错误密钥不得自动覆盖任一副本。

## 测试

- 新业务逻辑补充单元测试。
- 修复缺陷先写回归测试。
- 加密测试至少包含正常回读、错误 AAD、错误密钥和密文篡改。
- 数据库迁移测试应从空库和上一已发布版本执行。
- 平台截图变化必须分别在 macOS 和 Windows 真机验证。
