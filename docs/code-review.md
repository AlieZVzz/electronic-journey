# 代码审查规则

按优先级审查：

1. 数据泄露、权限扩大、密钥处理、AEAD 验证、路径穿越、删除和升级签名问题。
2. 截图状态与真实状态不一致、失败被误报成功、重试或恢复导致丢数据。
3. 跨平台差异、休眠唤醒、多显示器热插拔、时区和文件原子性。
4. API 或数据库兼容性、幂等性和迁移可回滚性。
5. 测试遗漏、可维护性和不必要依赖。

审查时确认：

- 前端是否只调用必要且受校验的 Tauri 命令。
- 新能力是否需要调整 capability，调整是否保持最小权限。
- 日志是否可能包含截图、路径中其他文件名、密钥、令牌或预签名 URL。
- 所有“成功”状态是否有文档要求的验证证据。
- 删除是否幂等且不会因局部失败造成状态不一致。
- 用户关闭、暂停或撤销权限后是否确实停止捕获。

输出按高风险、中低风险、建议优化和待确认问题组织。没有发现时明确说明验证范围和剩余盲区。
