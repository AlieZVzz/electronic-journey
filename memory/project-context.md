# 项目上下文

## 背景

Electronic Journey 帮助个人用户留存自己的工作、学习和创作过程。产品的差异化不是采集更多内容，而是在持续记录场景中保持知情、可见、可暂停、可撤销，并让用户主动选择本地图片进行 AI 分析。

## 关键约束

- Windows 和 macOS 使用同一产品，但截图和系统安全存储由平台适配器实现。
- 默认每 5 分钟捕获，空闲 10 分钟后暂停，锁屏和休眠时不捕获。
- 本地原图使用无损 WebP 并保留平台捕获的像素尺寸；时间线缩略图最大宽度为 1440 像素，今日页显示最新原图。
- 新截图默认以普通 WebP 原图和缩略图保存在本机。
- 不建设自有图片云端、对象存储或服务端 LLM 中转。
- 本地截图与 AI 分析解耦，LLM 请求失败不得阻止本地保存。
- 只有用户选择图片并确认后，Rust 客户端才直连配置的 LLM 提供商。
- 第一阶段不做隐蔽运行、键盘记录、实时直播或自动图片分析。

## 重要外部依赖

- macOS ScreenCaptureKit 与 Keychain。
- Windows.Graphics.Capture 与当前用户作用域 DPAPI。
- Tauri 2 runtime、capabilities 和 updater。
- SQLite 与未来的 Rust LLM 提供商适配器。

## 当前状态

macOS 原型已具备主动授权后的真实截图、普通 WebP 与缩略图原子写入、SQLite 时间线和启动索引恢复。Windows 捕获、系统状态监听、托盘、LLM 凭据和提供商适配器仍待实现。
